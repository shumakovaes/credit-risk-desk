# Повторная проверка перед демонстрацией

Дата: 5 ноября 2026. Проверка включала запуск свежей копии с GitHub, граничные входные данные, финансовые расчёты и воспроизводимость модели.

## Найдено и исправлено

- ID счёта выше диапазона PostgreSQL integer вызывал HTTP 500 при вызове SQL-функции признаков. Теперь ID, регион и смещение списка ограничены до обращения к БД; неверный запрос получает HTTP 422.
- Положительный доход порядка `5e-324` приводил к бесконечной долговой нагрузке и ошибке сохранения JSON. Минимальная положительная денежная величина в API теперь 0,01 CZK.
- Некорректные JSON-числа `NaN`/`Infinity` отвергались Pydantic, но само сообщение об ошибке не сериализовалось. Обработчик возвращает HTTP 422 с полем и причиной, без исходного значения.
- Fingerprint одинаковой обучающей выборки различался между Windows и Linux из-за переносов строк CSV. Для хеширования явно задан LF.

## Дополнительные проверки

- Свежий clone коммита `5c6eb7cc745e9bceec0fbd9e52964497758c3016` собран в отдельном Compose-проекте `review-risk` без `.env`, исходных данных и модели. Изменены только внешние порты для параллельного запуска. Демонстрация содержит 48 кредитов; API и UI доступны.
- Создана заявка, затем остановлены и повторно запущены UI, API и PostgreSQL. Сохранённый JSON заявки остался неизменным. Повторный init не заменил базу.
- Для 64 комбинаций суммы, ставки и срока платёж независимо проверен дисконтированием потока в Decimal с точностью 60 знаков. Включены нулевая и очень малая ставка, 100% годовых, 600 месяцев и сумма 100 млн CZK. Расхождение не превышает округление до копейки.
- После исправления заново обучена модель на Berka в Windows. Fingerprint и версия `ba88ef9eb190` совпали с Linux, состав train/validation/test и метрики совпали. [Повторное обучение](../reports/review-training-report.json). Рабочий артефакт приложения не перезаписывался.
