# Бизнес-правила

Конфигурация: `config/rules.json`, версия `educational-v1`. Пороговые значения выбраны для демонстрации и не являются политикой реального банка.

| Проверка | Условие прохождения | Нехватка данных |
|---|---|---|
| Сумма | 1 000–1 000 000 CZK включительно | Некорректный вход → HTTP 422 |
| Срок | 6–60 месяцев включительно | Некорректный вход → HTTP 422 |
| Доступный лимит | Сумма ≤ введённого лимита | unknown |
| Нагрузка | (новый платёж + действующие платежи) / заявленный доход ≤ 45% | unknown, если нет дохода или действующих платежей |
| История | Возраст счёта ≥ 90 дней, есть операции в окне | unknown |

Лимит равный нулю известен и означает отсутствие доступного лимита. Нулевые действующие платежи известны и допустимы. `null` означает, что информация неизвестна. Доход должен быть положительным. Ноль и отсутствие данных не смешиваются.

Результат:

1. Есть `failed` → `rule_violation`.
2. Иначе есть `unknown`, отсутствует модель или модель выше порога → `manual_review`.
3. Иначе → `checks_passed`.

`checks_passed` — завершение учебных проверок, не одобрение кредита. Высокая оценка модели вызывает ручную проверку и не подменяет результат отдельных бизнес-правил. Приоритет нарушения правил выше требования ручной проверки; оба основания остаются в полном отчёте.

Внутренние лимиты банка не подключены. Каждая причина указывает, что лимит и доход введены пользователем. Отчёт хранит дату расчёта, режим данных, параметры, версию правил, оценку и версию модели.

Калькулятор использует номинальную годовую ставку в процентах, месячную ставку `r = annual_rate_pct / 1200` и аннуитет `P × r / (1 − (1+r)^−n)`. При r=0 платёж P/n. Итоговые суммы вычисляются до округления ежемесячного платежа; последний фактический платёж может отличаться на копейки. Комиссии, страховка, эффективная ставка, досрочное погашение и банковский календарь не моделируются.
