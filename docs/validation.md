# Фактически выполненная проверка

Дата: 5 ноября 2026. Проверены локальное окружение Windows (Python 3.12.14, PostgreSQL 17) и Linux-контейнеры в Docker Desktop. Docker Engine 27.3.1, Compose 2.30.3-desktop.1. Зависимости зафиксированы в `requirements.lock`.

## Проверено

- Применена миграция Alembic к трём отдельным пустым базам: demo, Berka и test.
- В demo загружены 60 клиентов, 60 счетов, 48 кредитов, 2 880 операций. Повторная инициализация не заменяет набор.
- В Berka прочитаны все восемь исходных файлов. Clean: 5 369 клиентов, 4 500 счетов, 682 кредита и 1 056 320 операций. Импорт завершился одной транзакцией без ошибок проверок.
- Обучена модель на реальных завершённых кредитах. Сохранены pipeline, версия, ID train/validation/test, порог и метрики. [Полный отчёт](../reports/training-report.json), [хеши данных](../reports/data-manifest.json).
- **28 тестов пройдены, без пропусков** при заданной `TEST_DATABASE_URL`. Unit: расчёты, правила, валидация данных, train-only preprocessing, сериализация pipeline, порог по стоимости. PostgreSQL/API: временные границы, совпадение признаков двух путей, защита от перезаписи, запрет ML-метрик на синтетике, контракты, журнал, CSV. UI: все пять разделов и отправка форм через Streamlit AppTest с настоящими API и PostgreSQL. [JUnit](../reports/test-results.xml).
- API и Streamlit запущены отдельными процессами. Через HTTP создана заявка на Berka с настоящей обученной моделью. [Сохранённый ответ](../reports/api-smoke.json).
- В настоящем headless Chrome открыты портфель и форма заявки, выполнено сохранение, отображены объяснения модели и графики. Ошибок JavaScript не обнаружено. Скриншоты: [портфель](../reports/portfolio.png), [заявка](../reports/application.png). Они также просмотрены визуально.
- `python -m compileall` и `docker compose config --quiet` выполнены успешно.
- Отдельный локальный Git-репозиторий инициализирован. Исходные ASC, `.env`, окружение и обученный joblib исключены из Git.

Есть предупреждение зависимости Starlette о будущем отказе от httpx в TestClient. Оно не мешает текущим тестам; httpx и Starlette зафиксированы в lock-файле.

## Дополнительно проверено в Docker

- Собраны образы init, API и UI. PostgreSQL, API и Streamlit запущены, все три healthcheck имеют статус `healthy`; одноразовый init завершился с кодом 0.
- В контейнерную базу импортированы реальные данные Berka: 682 кредита и 1 056 320 операций. Шесть ранее сохранённых локальных заявок перенесены с исходными ID; проверено наличие каждой из них.
- **28/28 тестов пройдены внутри Linux-контейнера** на отдельной PostgreSQL-базе `creditdesk_test`, без пропусков. [Docker JUnit](../reports/docker-tests.xml).
- Обучение повторено внутри контейнера в отдельный каталог `artifacts/docker-validation`. ROC-AUC 0,68699, AP 0,44930, Brier 0,10984; исходный артефакт приложения сохранён. [Отчёт обучения в Docker](../reports/docker-training-report.json).
- Через опубликованные порты повторно проверены HTTP API, сохранение заявки и интерфейс в Chrome. Скриншоты портфеля и заявки обновлены после перехода на контейнеры.
- Добавлены проверка здоровья UI и `restart: unless-stopped` для постоянно работающих сервисов. [Состояние контейнеров, проверки и перенос данных](../reports/docker-validation.json).

## Что не подтверждено этим прогоном

- GitHub Actions: workflow подготовлен, но репозиторий не опубликован и удалённый CI не запускался.
- Публичное размещение, многопользовательский доступ, нагрузочное тестирование и реальные банковские интеграции не выполнялись.

Результат обучения не следует путать с проверкой продакшен-модели: всего 47 наблюдений и 6 проблемных кредитов в test, нет временного backtest и данных о датах окончательной доступности статусов.
